# Magnus SDK 更新记录

[English](CHANGELOG.md)

## 1.0.0

相对已发布 0.8.2 的变更：

- 支持以 Dockerfile 文本替代 `container_image`，提供能力检查、独立构建状态与
  构建日志接口；构建上下文为空，与任务仓库无关。
- 支持选择 `execution_target`、发现已配置目标，并通过 `node_count` 和
  `tasks_per_node` 指定多节点 Slurm 拓扑。
- 支持不消耗下载次数的 custody 就绪查询，以及下载前可选等待。具备对应能力的
  控制面可在任务运行中导入产物，并在执行结束后起算关联产物的领取期限。
- 对至少 8 MiB 的载荷与支持的控制面协商可续传上传；旧控制面仍用 multipart。
  续传覆盖同一次 SDK 调用，不自动跨客户端进程退出恢复。
- 上传结果不确定时抛出 `UploadOutcomeUnknown`，避免盲目重复发布。传输或解包
  失败保留原下载目标；包括 Python 3.10 在内的版本均拒绝不安全的归档条目。
- 分发 `py.typed` 类型标记，保留仅通过源码注入 SDK 的导入方式。
- CLI 按职责拆分并保留命令入口，修复纯数字 Job ID 识别与时间戳解释。

### 兼容性

最低 Python 版本仍为 3.10。原有容器镜像、Python Blueprint 与 SDK 配置继续
支持。新功能需要服务端支持；显式 Dockerfile 或执行目标请求在旧服务端明确报错。

`submit_job`、`execute_job` 及其异步和模块级版本保留已发布 0.8.2 的位置参数
顺序。新增提交字段仅接受关键字。如果使用未发布源码版本，并曾按位置传入
`node_count` 或 `tasks_per_node`，升级时需为这两个参数写明名称；关键字调用的
含义保持不变。
